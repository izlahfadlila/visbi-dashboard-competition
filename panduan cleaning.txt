# Panduan Penyusunan Notebook EDA & Data Cleaning

## Tujuan

Notebook ini bertujuan untuk melakukan proses **Exploratory Data Analysis (EDA)**, **Data Cleaning**, dan **Validasi Integritas Data** sebelum data digunakan untuk pembuatan dashboard (Power BI).

Karena dataset menggunakan **star schema** (Data Warehouse), proses analisis **tidak dilakukan sekaligus**, tetapi **dilakukan per tabel** sesuai karakteristik masing-masing.

---

# Struktur Notebook

Notebook disusun dengan urutan sebagai berikut.


# Dataset

## Dimension Tables

- dim_date
- dim_channel
- dim_campaign
- dim_ad_content
- dim_kol
- dim_product
- dim_customer

Dimension table berisi **master data** sehingga fokus utama adalah:

- kualitas atribut
- konsistensi data
- duplicate key
- missing value
- validitas kategori

---

## Fact Tables

- fact_marketing_daily
- fact_web_events
- fact_orders
- fact_budget

Fact table berisi **data transaksi atau aktivitas** sehingga fokus utama adalah:

- validitas nilai numerik
- foreign key
- konsistensi tanggal
- duplicate transaksi
- anomali data

---

# Workflow untuk Setiap Tabel

Setiap tabel dianalisis menggunakan alur berikut.

## 1. Gambaran Dataset

Lakukan pemeriksaan awal terhadap dataset.

Minimal meliputi:

- shape
- head()
- sample()
- info()

Tujuan:

- mengetahui jumlah baris
- jumlah kolom
- nama kolom
- tipe data
- indikasi missing value

---

## 2. Statistik Deskriptif

### Kolom Numerik

Analisis:

- mean
- median
- std
- min
- max
- quartile

### Kolom Kategorikal

Analisis:

- jumlah kategori
- frekuensi
- kategori paling dominan

---

## 3. Missing Value Analysis

Analisis:

- jumlah missing
- persentase missing
- kolom mana yang memiliki missing
- informasi text missing masih wajar gimana dan yang perlu ditangani gimana

Visualisasi jika diperlukan.

---

## 4. Duplicate Analysis

Periksa:

- duplicate row
- duplicate primary key

Contoh:

- customer_id
- product_id
- campaign_id
- order_id
- dll.

---

## 5. Unique Value Analysis

Lakukan pengecekan:

- jumlah unique tiap kolom
- value_counts() untuk kolom kategorikal

Tujuan:

- menemukan typo
- inkonsistensi penulisan
- kategori yang tidak semestinya

Contoh:

```
Male
male
MALE
```

harus diseragamkan.

---

## 6. Data Type Validation

Pastikan tipe data sudah sesuai.

Contoh:

Tanggal

```
object
```

harus diubah menjadi

```
datetime
```

ID sebaiknya bertipe string bila tidak digunakan untuk operasi numerik.

---

## 7. Distribusi Data

Untuk kolom numerik lakukan analisis distribusi menggunakan:

- histogram
- density plot (opsional)

Tujuan:

- memahami persebaran data
- melihat skewness
- melihat kemungkinan outlier

---

## 8. Outlier Analysis

Gunakan:

- Boxplot
- IQR
- Z-score (jika diperlukan)

Catatan:

Tidak semua outlier harus dihapus.

Outlier hanya dihapus apabila benar-benar merupakan kesalahan data. ini nanti aku yang analisis sendiri dulu jangan langsung kamu hapus sendiri

---

## 9. Validasi Nilai

Periksa apakah terdapat nilai yang tidak logis.

Contoh:

- umur negatif
- harga negatif
- quantity negatif
- CTR > 100%
- conversion rate > 100%

---

# Data Cleaning

Setelah seluruh analisis selesai, lakukan cleaning.

Cleaning dilakukan seminimal mungkin agar tidak menghilangkan informasi penting.

Cleaning dapat berupa:

- menghapus duplicate
- memperbaiki tipe data
- mengisi missing value
- menghapus missing jika memang diperlukan
- memperbaiki typo kategori
- trimming whitespace
- menghapus karakter yang tidak diperlukan
- memperbaiki format tanggal
- standardisasi penulisan

Seluruh proses cleaning harus diberi komentar yang menjelaskan alasan dilakukan cleaning.

---

# Panduan Khusus Dimension Table

Dimension table adalah master data.

Fokus analisis:

## Primary Key

Harus:

- unik
- tidak boleh null

---

## Atribut Kategorikal

Periksa:

- typo
- inkonsistensi kapital
- inkonsistensi spasi

---

## Missing Value

Evaluasi apakah atribut wajib.

Contoh:

customer_id

tidak boleh kosong.

Sedangkan:

first_purchase_date

mungkin masih diperbolehkan kosong.

---

## Data Konsisten

Contoh:

Gender

```
Male
Female
```

Jangan sampai terdapat:

```
male
Pria
Laki-laki
M
L
Perempuan
Wanita
Female
F
```

apabila memang standar hanya dua kategori.

---

# Panduan Khusus Fact Table

Fact table merupakan data transaksi.

Analisis tambahan yang perlu dilakukan.

## Foreign Key

Pastikan seluruh foreign key terdapat pada dimension table.

Contoh:

customer_id

harus terdapat pada

dim_customer.

Lakukan validasi untuk seluruh foreign key.

---

## Nilai Numerik

Periksa apakah terdapat:

- revenue negatif
- quantity negatif
- cost negatif
- budget negatif

---

## Duplicate Transaction

Pastikan transaksi tidak tercatat dua kali.

Gunakan primary key transaksi apabila tersedia.

---

## Validasi Waktu

Pastikan:

- tanggal valid
- tidak di luar periode analisis
- tidak ada tanggal yang mustahil

---

## Business Rule Validation

Contoh:

CTR

harus berada pada rentang

```
0 - 100%
```

Conversion Rate

harus berada pada rentang

```
0 - 100%
```

Revenue

minimal

```
>= 0
```

---

# Analisis Relasi Antar Tabel

Tahapan ini merupakan bagian penting karena dataset menggunakan konsep Data Warehouse.

Tujuan:

memastikan integritas data sebelum dashboard dibuat.

Lakukan validasi untuk seluruh foreign key.

Contoh:

Fact Orders

↓

Customer

```
fact_orders.customer_id
```

harus terdapat pada

```
dim_customer.customer_id
```

Lakukan juga untuk:

- product_id
- campaign_id
- channel_id
- ad_id
- kol_id
- date_id

dan seluruh foreign key lainnya.

---

## Yang perlu diperiksa

### Missing Foreign Key

Apakah ada foreign key yang tidak memiliki pasangan pada dimension table.

---

### Orphan Record

Apakah terdapat transaksi tanpa master data.

---

### Cardinality

Pastikan relasi sesuai desain star schema.

Umumnya:

Dimension

```
One
```

ke

Fact

```
Many
```

---

### Duplicate Primary Key

Pastikan seluruh dimension table memiliki primary key yang unik.

---
